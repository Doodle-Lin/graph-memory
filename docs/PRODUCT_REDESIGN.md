# Graph Memory 产品设计规格

> 2026-11-02 实施更新：主流程恢复为 Agent 经 MCP 自动检索与沉淀；桌面负责接入状态、浏览和纠正，手动复制仅备用。旧原型与下述阶段设计作为历史依据，最新运行方式见 [桌面说明](../desktop/README.md)。已实现独立服务、范围隔离、版本修订和 Avalonia 开发版；迁移、语义检索、删除恢复等仍未完成。


版本：1.1，2026-11-02。状态：设计已收敛，用户确认“现在够直接，可以收敛设计”。实施、专项可用性与真实效果测试尚未开展。
本文是重设计的唯一现行规格；design/REVIEW_ROUNDS_1_3.md 保留历史推演，不再作为互相覆盖的实施要求。设计审计见 design/REVIEW.md。

## 1. 产品承诺和边界
为日常使用多个 Agent 的个人提供两层记忆：项目中的工作上下文，以及跨项目可复用的个人经验。帮助下一会话少重复解释、少重复失败、保留未解决阻塞，并在新工作中用到过去学到的方法。桌面端必须使用 Avalonia 重做；记忆服务优先保留 Rust，引擎重写不是本次目标。
主要入口在 Agent 工作流，桌面端用于了解、核查和纠正。手动复制是兼容兜底，不作为长期主要操作。
不做任务执行器、团队协作、云同步、通用文档库或图谱编辑器。稳定规则留在 AGENTS.md，正式方案留在项目文档；本工具组织动态状态和证据，不成为第二份隐形规范。
价值假设：跨来源整理节约的时间大于接入、审核、纠错成本；来源展示能减少错误使用；项目隔离能减少无关记忆。均需对照试验，尚未证实。
若价值实验失败，缩减自动捕获和摘要范围，保留可追溯交接；不撤销用户明确要求的 Avalonia 方向，也不盲目扩大功能。

## 2. 当前产品为何需要重做
静态证据：frontend/index.html 主入口为检索/导入/提炼，详情/图谱组织内容；saveEdit 取选中 ID 却以文本 query 更新。agent_connector.rs 的 connected 表示配置存在。engine.rs 的 node_history 不等于完整可逆事务。mcp_server.rs 已是独立 stdio 代理，依赖桌面进程 HTTP 引擎。
结论：产品面向存储对象而非用户工作；修改对象和连接状态表达需要准确；独立代理存在不等于后台服务已独立。
未开展旧应用运行走查，不能据此断言具体渲染、性能或崩溃表现。

## 3. 核心对象及不变量
- Project：稳定 UUID、显示名、用户关联目录；目录改名保持项目身份。项目事实不可跨项目默认混入；个人经验按相关性另区召回并保留原案例。
- TaskRef：轻量任务引用（ID、项目、标题、active/paused/done、可选外部链接）。不复制完整任务管理系统；无任务时可项目级恢复。
- Evidence：来源定位、必要摘录、内容指纹、主体、采集时间、可访问状态。原文与指令分离，不执行记忆中的命令。
- Record：ID/版本、memory_scope（project/personal）、项目在project范围必填而personal范围可为空、任务可选、类别（决策/状态/阻塞/尝试/下一步）、内容、证据、subject_key、scope。分别记录发生/生效/采集时间，未知不猜。
- scope：仓库、分支或提交、环境、有效时间窗。未知范围不能升格为全部环境。
- 生命周期：候选/当前/已替代/撤回。依据类型另列：用户确认/工具结果/Agent陈述/推断。确认不是工具验证，工具结果只证明其执行范围。
- Change：修改前后版本、原因、主体、证据。撤销恢复紧邻前一版本并生成新版本；遇到后续依赖或版本冲突不能盲目覆盖。
- ContextBundle：项目/任务/范围、生成时间、输入版本、选择与排除原因、缺口；每个条目内联 ID、版本、依据、有效时间、来源。记录更改后旧包失效，保留历史不篡改。

硬约束：写入/更新按准确 ID 与 expected_version；不按相似度选择修改对象。相似记录只关联，V1 不做破坏性自动合并和自动遗忘。候选可进入“未核实陈述”分区，不能被压缩成事实断言。收到结果、引用结果、正确使用结果是三个不同指标。

## 4. 第一次使用与日常路径
### 首次使用
1. 欢迎页只说明“让下次会话接着工作”，提供“关联项目目录”。不要求先理解 embedding、图谱或配置 LLM。
2. 本地选择目录，输入/确认项目名；若已关联则进入原项目。已有旧记忆先放“历史未归属”，不猜测全部归属。
3. 选择一个检测到的 Agent。展示将修改的配置范围并备份；接入失败保留原配置，给出明确错误和重试。允许跳过并手动记录。
4. 执行合成握手与读写检查，分别报告配置/握手/调用。实际宿主不调用时显示“尚未收到调用”，不显示成功。
5. 没有数据时提供“记录一次交接”，只需填写做了什么、尚未解决什么及来源可选；没有来源的内容明确为陈述。模型未就绪也可完成此流程。
第一次价值：另一会话能读到这份交接及其不确定性。不是看到节点计数增长。

### 日常自动捕获
支持事件：decision_recorded、verification_finished、blocker_changed、handoff_saved、correction_requested。来源为显式 MCP 写入或用户选择导入，不后台读取所有聊天文件。
事件必填 memory_scope、event_id、producer、kind、occurred_at（可未知）、body；project范围必填project_id，personal范围允许无项目；可选 task_ref、scope、evidence_refs、origin_project_id。工具验证结果要求命令/运行 ID、退出状态、适用提交；缺失时降为陈述。
服务先校验项目、来源和版本，在事务中持久化，再确认 received。相同 producer+event_id 重试返回原结果，不能重复创建。暂时失败返回可重试且不宣称已保存；适配端最多自动重试3次，之后显示待提交并保留草稿，不无限阻塞 Agent。
服务只承诺收到的事件，不能假定 Agent 会主动调用。首版只发布一个经过真实端到端验证的适配器，其他标实验性。未捕获时用户能手工留交接，而非被迫重新接入。
低风险记录自动归档，矛盾与归属不明聚合待处理；不要求逐条批准。任务结束/发生关键决策时写入，避免每次回答写入噪声。

### 再次开工
Agent 传入 project_id、可选任务/范围和上下文预算。结果先列当前目标/约束、未解决阻塞和下一步，再列相关决策/尝试；不能容纳必要阻塞时明确“上下文不完整”，不能悄悄截断。
桌面“继续工作”直接生成同一结果，复制按钮立即可用；背景和证据默认折叠，按需查看。来源不可核实的内容用“某主体于某时声称”表达。

## 5. 桌面信息架构与交互
左侧项目与全局搜索，中间项目续接页，右侧按需证据。主页面优先当前状态、阻塞、下一步、近期变化；没有全图默认加载和装饰性统计仪表盘。
项目切换清空当前选择/上下文预览，保留按 project+record+version 隔离的未提交草稿，并提示数量。不得把项目 A 的草稿保存到项目 B；返回时重新校验版本。
全局搜索显式进入，结果标明项目；从结果跳转先切换对应项目再显示详情。图谱为后续辅助探索，不影响 P0。
记录详情显示正文、依据、适用范围、时间、来源、版本与历史。编辑标题“纠正这条记录”，保存动作不能创建其他近似节点。冲突时保留草稿，展示最新内容和差异，用户重新确认后提交。
冲突候选最小规则：相同项目+subject_key、scope相交、单值结论不同；支持手工标记。自由文本归一化仅提议，不宣称能发现任意语义矛盾。处理方式：明确替代、补范围后并存、暂不确定。
证据与结论同屏阅读，使用普通语言而非数据库字段名。颜色不独自承载状态。键盘可进入全部操作，缩放200%不遮挡主要按钮；长内容折叠可展开，编辑草稿不因面板切换丢失。

## 6. 来源变化与错误恢复
来源变化检查：用户打开证据或生成 bundle 时核对可访问性与指纹；文件大/服务慢导致超时则标“未重新核查”，不假装未变。
内容变化：旧证据仍是历史观察；依赖它的当前结论标待复核，受影响旧 bundle 失效。重新采集生成新证据版本，不自动替代结论。只有生成时检查而非持续监视时，应显示最后核查时间。
来源删除：显示保留摘录及“原始来源不可访问”，允许继续作为历史陈述；当前完成状态不能据此升级。
服务离线：显示上次成功读取的只读快照和时间，支持本地草稿，不生成当前 bundle、不保存到服务。重连重新取版本再提交。UI 不绕过服务直写数据库。
模型未就绪：浏览/手工记录仍可用；语义搜索不可用时明确降级到关键词或提示不可用，不假装完整召回。
拒绝或失败的写入保持旧状态；长任务有进度、取消/重试，取消不得回滚已明确提交的其他任务。

## 7. 后台服务与 Avalonia 的迁移契约
目标组件：Avalonia 客户端、Rust 独立服务、现有 MCP 代理演进。Rust 进程不依赖 Tauri 窗口；UI 只通过版本化 API 访问。
启动：客户端/MCP 请求服务→单实例仲裁→协议与库版本检查→就绪。启动竞争不能创建两个写入者。服务未就绪时返回明确状态，不占用宿主120秒无反馈。
关闭窗口默认不退出已启用的后台记忆，首次关闭清楚说明；“退出记忆服务”独立入口，说明 Agent 暂不可用。开机启动为可选择设置，不默默启用。
生命周期状态：未启动/启动中/就绪/降级/故障/升级中。故障可重试启动，连续失败停止自动重试，保留诊断。
兼容：UI/API/数据库分别版本化，未知重大版本拒绝写入。传输仅限本机，运行用户权限内服务；具体鉴权实现为技术验证项，不把 localhost 当作完整隔离。
迁移：备份→在副本迁移→核对记录/来源/引用完整性→关闭旧写入者→切换；旧端不直接访问新 schema。保留旧 ID 和来源，不伪造项目归属/证据。失败恢复旧库；切换后新增变更另行导出，不静默丢弃。
安装验证覆盖首次安装、升级失败、重启、窗口关闭、后台退出、MCP 单独启动、备份恢复、旧端并存拒绝写入。框架/API/打包细节需技术验证，不在设计阶段声称已完成迁移。

## 8. 数据控制与运行成本
本地默认。外部 LLM 提炼关闭时仍能记录、关键词检索和生成结构化上下文。启用前展示发送范围和成本来源；用户可停止，不自动扫描/发送整机目录。
日志默认只存工具名、项目、时间、结果、ID/版本、耗时，7天滚动；不含 prompt、原文或密钥。允许清除和关闭，关闭后显示相关状态不可观测。详细日志单独启用并到期。
来源导入做敏感内容提示与排除预览；扫描不保证发现全部秘密。来源中的指令保持数据边界，工具不因记忆内容执行命令；宿主是否服从恶意内容在集成验收中单测。
项目支持导出结构化记录与来源索引；移除项目先说明保留/移除哪些数据，软删除可恢复。永久清除是独立操作，关联缓存、索引、日志和备份保留策略必须展示，不承诺能撤回已复制给 Agent 的内容。
效率约束为待测目标：已有缓存的项目页在2秒内可用；后台提炼不阻塞浏览；超时给出降级。测试规模和机器配置应记录，不能用空库速度代表真实使用。

## 9. 范围、交付与价值验收
第一纵向切片：一个项目、一次有出处交接、一次纠正、一次真实 MCP 读取、一个 Avalonia 续接页。它不是完整 V1。
V1 P0：项目隔离、范围/来源/版本、事件写入与重试、确定性上下文、纠错和撤销、单一实测适配器、首启/故障/备份迁移、调用可观测。旧自动破坏性去重/遗忘必须停用或隔离。
P1：导入效率、更多适配器、上下文压缩、可逆合并。P2：图谱探索、多平台。根据使用证据调整，不以实现容易程度代替价值排序。
设计交付门：规格无冲突、关键路径和异常有明确状态与动作、原型与规格对应、验收可重复、阻断问题明示。设计通过不等于产品效果或实现通过。
实现门：冻结案例与数据库，真实服务/宿主跑通；迁移、安装、故障验证。视觉/键盘/缩放检查独立于脚本测试。
价值门：至少3项目12个预注册续接案例，与仅文档及旧工具比较；输入来源相同、独立会话、交替顺序、记录人工审核/纠错/接入摊销时间。有效续接=正确下一步、保留必要阻塞、无无据状态断言、不要求用户重述已有关键事实。
暂定方向门槛：净准备时间中位数减少30%，硬错误为零；超过基线两倍耗时的案例逐一解释。小样本仅支持个人试用，不证明普遍效果。
固定案例和评分规范见 design/ACCEPTANCE_CASES.md。当前尚未执行真实对照实验。


## 10. 用户反馈后的简化原则（2026-11-02）
用户实际反馈：“看不出什么问题，不过实际使用我还是希望更简便一点”。这支持没有显著可见问题的初步观察，不等于完成键盘/缩放专项检查；更重要的需求是降低操作负担。
已接入后的正常路径：Agent自动获取当前项目上下文，用户无需打开桌面端。桌面手动路径固定：打开最近项目 → 继续工作。已接入Agent按当前项目和任务获取上下文；未接入时一键复制。不要求先选记忆、先核查来源、先确认每条事实。任务不明确时只问影响后续行动的最小问题。
首页只突出当前进度、阻塞与下一步；“继续工作”是唯一主动作。详细背景默认折叠，来源/纠错按需打开；配置、导出、接入放到更多操作。原型检验控件折叠，不属于正式产品导航。
不确定陈述不会强制打断续接：在提供的上下文中保留限定，只有不澄清会选错项目、泄露范围或执行错误动作时才阻断。风险不影响下一步时可带着缺口继续。
首启先关联一个项目即可开始；Agent接入和LLM设置可延后，不能连续要求用户配置多个面板。
简便性验收：已有项目从打开到获得可用上下文最多2次点击，不强制打开证据；已接入的普通续接无需桌面操作或审核；纠错只在发现错误时发生。指标与可靠性同时验收，不能通过隐藏错误或删掉阻塞换取少点一次。


## 11. 个人经验与项目记忆（用户新增确认）
项目不是记忆边界。用户可以在任何会话说“这个坑记一下”，无项目也能保存个人经验；不强迫创建项目或先填分类表。
经验记录保留：现象/问题、解决方法、适用条件、依据、原案例引用、待验证项。偏好亦可为个人范围，但不伪装技术规律。
项目中产生的可复用经验可提出沉淀建议；用户显式要求时直接保存为个人记录。项目事实不会仅因相似性自动升级成通用经验，原始事实与提炼经验通过来源引用关联。
检索分为“当前项目事实”和“相关个人经验”；二者都有范围/依据标签。无项目时只检索个人经验与用户明确允许的其他范围。其他项目事实不直接混入，个人经验中的原案例仅作解释，不改变当前项目状态。
经验失效或出现反例时产生新版本，保留适用条件和旧结论；不能因为新项目结果不同就静默覆盖所有历史。
桌面增加可独立进入的“经验库”，支持搜索、记录、纠正；不要求用户每天整理。项目续接仍保持自动和两步兜底。个人经验中敏感的原项目来源按授权边界展示，跨项目可用不等于允许外发。
实施顺序：M1独立服务不绑定project-only schema；M2同时实现project/personal范围和相应验收；Avalonia呈现项目与经验双入口。此处是新增产品契约，当前实验服务仍使用旧通用节点模型，尚未实现新的范围隔离。
