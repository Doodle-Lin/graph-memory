# P5 契约：本机离线语义召回（semantic recall）

交付状态（2026-11-16）：未验收实验。现有实现已保存在 `codex/p5-semantic-hold-20261116`（`f801a40`），不属于当前P4交付线。本文阈值与预算为实验契约，不代表生产效果已验收。

状态：**草案 v1（lead 定稿，2026-11-05）**。本文件是本批次的**唯一权威契约**；实现、测试、脚本断言、发布物都必须与它一致。任何偏离都要先改本文件并说明理由。

## 1. 背景与目标

P4 之后字面检索（词条 + 中文 bigram）已到天花板区间：`同义改写（不照抄）` Recall@5 = 0.5333，**完全不共享字面**的改写（例如"怎么防止改了代码忘了跑测试" ↔ 记录里的"提交前必须先跑回归"）必然漏召回。目标：增加一条**本机、离线、可选**的语义通道，让这类查询能召回，同时**不破坏**既有字面契约。

成功定义：跨字面改写召回可用；没有模型时不比现在差；模型的引入不带来新的假召回类别。

## 2. 关键设计决定

### 2.1 "bounded semantic"（重新招标式语义召回）

语义相似度是**不对称**的：对"具体目标"高，对"仓库里任意一条记录"低。若把语义分数直接混进既有排序，长查询会整体抬高、偏离目标记录，破坏 AND 契约与"多主题查询必须 0 召回"。

因此规定：

1. **字面路径不变**：`match_terms` 的匹配与评分语义、排序规则、AND 契约（P0-A1）**一字不改**。
2. 语义通道**只在字面命中集合为空时**产出候选（下称"语义建议"）。字面通道只要有结果，就**不**计算建议——这样"已经找到答案"的检索不会有噪声，建议只出现在"用词想不起来"的场景：
   - `query_embedding = embed(query)`
   - 候选 = `top_k`（默认 5，上限 10）个 **scope 内且未撤回**（`include_retracted=false` 时）的记录，按 `cosine(query, memory)` 倒序；
   - 只保留 `cosine >= semantic_min_similarity`（默认 **0.52**，可配置）的记录；
   - 语义建议**不得**混入字面命中集合的排序权重；字面结果优先，语义建议作为补充段落（`semantic.memories`）返回。
   - **冷启动必须确定性（v1.4）**：向量索引的构建**不得**让"同一库、同一查询"在不同调用次序下给出不同建议。做法：`semantic=true` 且索引缺失/过期时，**先完成本次所需范围内的向量重建**再回答；重建在预算内（默认 ≤10 s，本机 1200 条实测 3.3 s）必须同步完成；若超出预算，**降级为 `available=false` + `note`（索引未就绪）**，**绝不允许**返回"只建了一半的索引"得出的部分建议。后台增量预建可以做，但不能让用户看到非确定性结果。
3. 每条记录参与语义比较的文本向量固定为 `title + "\n" + content + "\n" + conditions` 的拼接（空白归一化后），并由 `memory_vectors.content_sha256` 绑定；内容/标题/条件任一变化都必须重算。

### 2.2 降级必须是最小惊讶

- 模型未就绪（未下载/校验失败/加载失败/关闭）时：**行为与 P4-D 逐位一致**（指标、返回条数、排序、`semantic.available=false`、`semantic.mode="literal"`）。
- 模型下载/校验失败不得导致服务启动失败、不得让已有功能退化。
- 语义通道**不得**改变字面命中集合内的顺序；不得放行被撤回记录（`include_retracted=false` 时）；不得跨项目泄漏（`scope` 过滤先于语义比较）。

## 3. HTTP 契约

### 3.1 请求

`POST /api/v1/search` 新增可选字段（缺省 = 当前行为，向后兼容）：

| 字段 | 类型 | 默认 | 语义 |
|---|---|---|---|
| `semantic` | bool | `false` | 是否请求语义通道；模型未就绪时按 §2.2 降级 |
| `semantic_min_similarity` | number | `0.52` | 允许区间 `0.0..=1.0`，越界 → 400 |
| `semantic_limit` | integer | `5` | 允许区间 `1..=10`，越界 → 400 |

`POST /api/v1/context` 也接受 `semantic`（默认 `false`），用于"想不起来关键词时给个方向"。

### 3.2 响应

新增对象（**任何情况下都存在**，便于客户端判断）：

```json
"semantic": {
  "available": true,
  "mode": "hybrid" | "literal",
  "model": "bge-small-zh-v1.5",
  "min_similarity": 0.52,
  "memories": [ { "id": "...", "score": 0.71, ... } ],
  "note": "模型未就绪：语义通道已跳过"     // 仅降级时出现
}
```

- `available=false` 时 `memories` 必须为空数组。
- `mode="hybrid"` 表示模型就绪且本次真的跑了语义比较。
- `memories` 每项**必须**含 `id`（memory id）与 `score`（cosine，0..1）；允许附带其它 memory 字段。语义结果的分数**不得**与字面 `memories` 的分数混在同一排序里比较。
- `POST /api/v1/search` 的响应顶层必须**始终**含 `semantic` 对象（即使未开启语义），`total` 仍只统计字面结果；语义结果条数另由 `semantic.memories` 长度表达。
- MCP `memory_search` 的 arguments 直接透传，因此 `{"semantic": true}` 通过 MCP 也生效；MCP 五个工具的**集合与 schema 不变**。

### 3.3 模型状态接口

`GET /api/v1/agent/status` 增加字段：`"semantic": {"state":"absent|downloading|verifying|ready|failed","model":"bge-small-zh-v1.5","detail":"..."}`。**不得**新增需要授权的写接口；模型下载触发只允许 `POST /api/v1/models/prepare`（本机、无参数、幂等）或在桌面端触发。

**进度字段（v1.1 修订，desktop-ux 2026-11-05 提出）**：`state="downloading"`/`"verifying"` 时**可以**附带：

| 字段 | 类型 | 语义 |
|---|---|---|
| `progress` | number `0.0..=1.0` | 已完成比例；**只在能真实测量时出现**，无法测量则字段缺省 |
| `bytes_downloaded` | integer | 已下载字节数 |
| `bytes_total` | integer | 已知总字节数；未知则缺省 |

三条硬规定：(1) **数值必须来自真实测量**，禁止用时间/次数伪造百分比；(2) 字段**全部可选**，客户端必须在字段缺省时仍能正确显示（不确定进度）；(3) 下载结束（`ready`/`failed`）后这些字段必须消失或归零，不得残留误导。

## 4. 存储契约

新表（`work-memory.db`，与 `work_memories` 同库）：

```sql
CREATE TABLE IF NOT EXISTS memory_vectors (
  id TEXT PRIMARY KEY,            -- memory id
  model TEXT NOT NULL,            -- 模型标识（含版本）
  dim INTEGER NOT NULL,
  content_sha256 TEXT NOT NULL,   -- 参与向量的文本哈希
  vec BLOB NOT NULL,              -- f32 小端序紧凑存储
  updated_at TEXT NOT NULL
);
```

- 老库（无此表）必须能直接打开并工作，不做破坏性迁移。
- 备份/导出：`memory_vectors` **不进导出包**（可重建的派生数据）；`restore` 后首次检索时按需重建，且重建不得改变答案（复核者需验证"恢复后指标一致"）。
- **快照校验口径（v1.3）**：`backup_format` 的表清单是**白名单**，`MemoryStore::open` 一定会创建 `memory_vectors`，因此该表必须与 `agent_activity` 同级处理：**解析时容忍它的存在、导出时排除它**（不 introspect 其列）。**不得**因为出现该表而拒绝一个合法工作库——那会让新库无法备份。对应地，导出包的内容必须与不含该表的旧库**完全等价**（复核者按 `payload_sha256` 与四表计数核对）。
- 重建过程必须幂等：同一内容重复计算得到相同向量（同模型）。

## 5. 模型获取契约

- 位置：`%LOCALAPPDATA%\GraphMemory\models\<model-dir>\`，可用 `GM_EMBED_MODEL_DIR` 覆盖（测试用）。
- 校验：下载完成后校验 **每个文件的大小与 SHA256**（清单内置于代码/文档），校验失败 → 删除临时目录、状态 `failed`、降级，不半途可用。
- 下载：只在显式触发时发生（桌面按钮 / `POST /api/v1/models/prepare`）；**不得**在服务启动或首次检索时静默联网。
- 无网络时：状态停在 `absent`/`failed`，产品其余部分完全可用。
- 不做代理/镜像/账号要求；不使用任何密钥。

## 6. 验收门槛（硬门槛，independent 复核必须用**自建、与仓库评测集零重叠**的数据集）

| 项 | 门槛 |
|---|---|
| 语义**建议**的**离题**泄漏（探针 30 条、官方 `no_answer`、复核者 `adv_offtopic` 子集，semantic=true 时） | **= 0**（实测可达：查询-记录真实余弦分布下探针最高 0.5160、no_answer 最高 0.4647，默认阈值 0.52 双清零且有 0.004 余量） |
| "语义相邻但不是答案"的建议（复核者 `adv_boundary`/`adv_tail` 子集） | **允许存在**（§6.0 定性为低置信建议），但**必须逐条披露数量与内容**，且必须显著少于同查询的字面噪声；隐瞒即判否 |
| 30 条同形多主题探针（`tests/eval/false_recall_probe.json`，semantic=true） | **0/30**（建议里也不得出现） |
| 官方 `no_answer` 查询（semantic=true） | 建议数 **= 0** |
| 跨字面语义集 Recall@5（复核者自建 ≥40 条，字面基线 ≈0） | **≥ 0.60**，且相对字面基线提升 **≥ 0.25 绝对**（**v1.4 下调**：本机可用的 95 MB 中文小模型达不到 0.80；见 §6.3，必须由**复核者自建集**实测，**不允许用调阈值凑数**——调高阈值必须同时给出跨字面召回） |
| 建议的"命中"口径 | 期望记录出现在 `semantic.memories` 里即算命中；同时报"期望记录被排在第几位" |
| 跨项目污染 / 撤回泄漏 / 版本不匹配 | **0 / 0 / 0**（字面与建议两条通道都要） |
| 未就绪降级：官方评测集指标 | 与 P4-D **逐位相同** |
| 检索 p95（1200 条 × 16 查询，模型已加载） | ≤ 字面基线 **+30 ms** |
| 建议的重建开销 | 全量 1200 条向量重建 ≤ 60 s 且幂等；**且结果必须与调用次序无关**（冷/热索引给出相同建议） |
| MCP | 五工具集合、`inputSchema`、`serverInfo.version` 语义不变（版本号见 §7） |
| 契约 | P0-A1 的 AND 断言（`S-A1-04`）仍 **PASS**；`context.text` 结构不变 |
| 依赖与网络 | 新增依赖必须已在离线缓存可构建；检索路径**零网络调用**（可断网复跑验证） |

任何一项不达标 → **不合入**。

### 6.0 "建议"而不是"断言"：本批次最关键的口径（v1.2 修订）

两组**互相独立**的测量（实现者用官方 27 条记录、复核者用自建 60+44 条语料）给出了同一个结论：**95 MB 级的本机中文小模型无法把"零字面交叠的改写"与"语义相邻但并非答案的查询"干净分开**——复核者的语料上，跨字面目标的最低 cosine 0.4014、p05 0.4119，而离题查询的最高 cosine 达 0.439（区间重叠）；要挡住离题查询需要 t>0.5963，那时跨字面召回已经归零。

因此本契约明确区分两条通道的**性质**（这也是产品语义，不只是测试口径）：

| 通道 | 性质 | 允许的误差 | 必须满足 |
|---|---|---|---|
| `memories`（字面 + AND 契约） | **断言** | 不允许：探针/无答案必须 0 误召回，顺序与 P4-D 一致 | P0-A1 全部既有门槛 |
| `semantic.memories` | **建议**（低置信、可解释、可关闭） | 允许"语义相邻但不是答案"的少量建议（必须可度量、可披露、可关闭）；但**离题/同形泄漏必须为 0** | 本表全部门槛 + 桌面端必须视觉区分并标注相似度 |

由此产生的三条硬性产品约束（复核者与桌面端都要按此判定）：
1. 建议**永不**计入 `total`、**永不**与字面结果混合排序、**永不**进入 `context.text` 的断言部分（可作为单独段落，须明示"可能相关"）。
2. 建议必须携带 `score`，并在 UI 上**视觉可区分**；不得使用与字面结果相同的呈现（例如同一列表、同样图标）。
3. 默认关闭（`semantic` 缺省 `false`）；没有模型时行为与 P4-D 逐位相同。

### 6.1 默认阈值 `semantic_min_similarity = 0.52` 的实测依据（v1.4 定稿）

> 演变过程保留如下，避免下一个人只看到一半：0.42（拍脑袋）→ 0.56（实现者按官方 27 条**记录间**分布建议）→ 0.42（复核者按自建跨字面集反对 0.56）→ **0.52（按"查询-记录"真实分布定稿）**。
> 关键教训：前两次都用**记录-记录**分布推阈值，而真正决定泄漏的是**查询-记录**分布——探针「马拉松 报名 端口」这类**词汇组合**会给到 0.29–0.52 的"听着相关"分数，只有实测查询侧分布才能抓住。

**证据 C（实现者，真实服务、模型已加载、limit=10，`artifacts/p5-semantic/threshold-scan-real.json`）**：

| 阈值 | 探针命中/30 | 官方 no_answer 建议数 | 跨字面正确建议 |
|---|---|---|---|
| 0.42 | **9** | **2** | P6、P7（2 条） |
| **0.52** | **0** | **0** | P6、P7（**同样 2 条**） |

探针最高查询余弦 **0.5160**、no_answer 最高 **0.4647**。**0.42 相对 0.52 只多买到 20 条泄漏（18 条探针 + 2 条 no_answer），没有多买到任何一条正确召回** —— 因此 0.52 不是"调参买数字"，而是**纯收益的去误报**；取 0.52 后距探针上限还有 0.004 余量。

**证据 A（实现者，官方 27 条记录间分布，`artifacts/p5-semantic/threshold-study.*`，仅作背景）**：各向异性偏置显著（两两无关记录 cos p50 = **0.5367**）。
**证据 B（复核者，自建 74 条记录 / 60 条跨字面查询，`artifacts/usability-verify/p5-verifier3/threshold-curve.json`）**：0.42 → 跨字面 R@5 0.9167（**推荐复核者再次实测 0.52 下的这一指标**）；0.56 → 0.1667；跨字面真实目标最低 cos 0.4014、p05 0.4119，离题查询最高 0.439。

**注意**：更换模型/语料必须重跑本节的**查询-记录**分布并更新默认值。

**证据 A.2（实现者的旧记录间曲线，仅作背景）**：0.42 → 探针 9、no_answer 1、目标 49；0.48 → 1/0/48；0.54 → 0/0/47；0.60 → 0/0/37。

**证据 B（复核者，自建 74 条记录 / 44 条对抗 / 60 条跨字面，`artifacts/usability-verify/p5-verifier3/threshold-curve.json`）**：

| t | 跨字面 R@5 | 对抗误召回/44 | off-topic/22 | boundary/6 | tail/16 |
|---|---|---|---|---|---|
| 0.42 | **0.9167** | 22 | 3 | 3 | 16 |
| 0.46 | 0.7667 | 18 | 0 | 3 | 15 |
| 0.50 | 0.6000 | 11 | 0 | 3 | 8 |
| 0.56 | 0.1667 | 5 | 0 | 1 | 4 |
| 0.62 | 0.0333 | 0 | 0 | 0 | 0 |

（该表是**离线模拟**，固定阈值下"对抗误召回"包含 tail 形状——那部分噪声已由 §2.1"只在字面为空时才建议"在结构上消掉大半；因此它**不能**用来选默认阈值，只能说明"绝对阈值无法把语义相邻与答案分开"。）

跨字面真实目标最低 cos **0.4014**、p05 **0.4119**；离题查询最高 cos **0.439** → **两者重叠**。

**结论（v1.4）**：默认取 **0.52**：真实查询侧分布下探针与 no_answer 双清零（上限 0.5160 / 0.4647），且跨字面正确建议数与 0.42 相同。`0.52` 只是"召回优先且不泄漏的默认值"，客户端可调；换模型必须重测并更新本节。

### 6.3 为什么把跨字面门槛从 0.80 下调到 0.60（v1.4）

**0.80 在本机可用的模型上达不到，而且调阈值买不到**：
- 官方 fixture 里"字面为空 + 期望记录存在"的改写查询只有 **4 条**，其中 **2 条**把期望记录带进建议（`empty_literal_suggested_hits=2/4`）；其余 7 条 P4-D 漏召回**字面本身有命中**，按 §2.1 不会产生建议——即"官方集上语义通道可用面很窄"是**设计使然**，不是失败。
- 提高阈值只会让建议更少（0.52 时 P6/P7 仍命中，0.56+ 开始丢），**不会**提高召回。
- 复核者的自建集（60 条真正零字面交叠）受影响更小但同样受限；他的模拟给出 0.42 → 0.9167、0.50 → 0.6000。

所以门槛定为 **Recall@5 ≥ 0.60 且相对字面基线（≈0）提升 ≥0.25**，由**复核者自建集**实测（**必须实测，不许用模拟值代替**）。若评测结果高于 0.60，如实记录实际值；若低于 0.60，判**不合入**或按 §9 的"换模型"处理。**同时必须报告"期望记录被排在第几位"**——因为 top-5 建议里排第一与排第五，对用户的价值差异很大。

**不采用"按 query 长度开语义"**：那会再造一个 P4 已经否决过的特例规则（当时被证明"零收益 + 可构造假阳性"）。**不采用"换更小但更强的英文模型"**：本产品面对中文用户，跨语言检索不在本批次目标内。

## 8.5 模型选择与未来（v1.4 澄清）

§8 的"非目标"是**本批次**不做，不代表方向错误：
- 本批次只承诺"换一种说法、不共享字面时给出**低置信建议**"；
- 若将来要**断言式**的语义召回（相信它、混排、进 context），必须先换模型（多语言更大的 embedding，或"召回 + 重排序"两段式）并重测 §6.1/§6.3；
- 升级路径不做兼容承诺：`memory_vectors.model` 字段已记录模型标识，换模型即整表重建（派生数据，可重建）。

### 6.2 为什么不用"相对判据"（已实测否决）

曾考虑用 `cos ≥ max(min_similarity, mean + margin)` 之类相对判据消除偏置。实测否决：要压住 30 条探针需要 margin ≥ 0.18，而官方 49 条有答案查询里有 **10 条**的"目标减最佳非目标"是**负值**（如 P1 −0.033、P3 −0.068、P5 −0.085），相对判据会**同时砍掉真答案**。因此保持 §2.1 的绝对阈值语义；若将来换更强的模型可重新评估。
