## 4. 最差类别（这是基线最重要的部分）

### 4.1 同义改写（不照抄）：Recall@5 = 0.3333（5/15），MRR = 0.3000

这是**最差类别**，也是唯一的真实召回缺口。10 条漏召回的 query → 期望 → 实际：

| id | query | 期望 | 实际返回 | 返回数 |
| --- | --- | --- | --- | --- |
| P1 | 有没有哪种情况会让服务根本起不来 | L1（网关端口冲突阻塞联调） | 空 | 0 |
| P3 | 本地环境的外网访问凭据什么时候失效 | L6（证书过期阻塞联调） | L1 | 1 |
| P4 | 排查链路问题的先后顺序是什么 | L9（链路核对结论） | 空 | 0 |
| P5 | 请求经常慢到被判失败是什么原因 | L7（网关超时阈值 30 秒） | 空 | 0 |
| P6 | 晚上跑批把时间占满了怎么办 | B1（备份窗口被其它任务占用） | 空 | 0 |
| P7 | 演练之前该检查哪些东西 | B2（下一步核对备份文件大小） | 空 | 0 |
| P8 | 备份文件保存多久合适 | B3（决策：备份保留 14 天） | B2, B10 | 2 |
| P10 | 命令行的任务跑完了但后台还在跑 | L4（PowerShell 退出后子进程被终止） | 空 | 0 |
| P11 | 本地端口老是起不来我该先查什么 | PE1（端口冲突先看残留进程） | 空 | 0 |
| P13 | 为什么打一句很长的话反而不容易找到东西 | PE3（长中文问句检索容易漏召回） | 空 | 0 |

### 4.2 根因：全词条 AND，且长中文 query 被整体当成一个词条

当前策略（`memory_store.rs` `match_terms` / `Term::parse`）是：query 按空白切分，**每个词条都必须命中**；
长度 > 2 的纯中文词条只在"原文子串"或"至少 2 个字符 bigram 命中"时算命中。

以 P1 为例：query 无空格 → 整句是一个词条，不含夹具原文任何 ≥2 个连续 bigram
（"服务"不出现在 L1 标题/正文，"根本起不来"也不出现），因此 `hits` 为假，`total=0`。
同样地 P4/P5/P6/P7/P10/P11/P13 全部 `total=0`：不是排序差，而是**一条都没进来**。

### 4.3 最小复现（两次运行都一致）

查询：`有没有哪种情况会让服务根本起不来`（scope=project，项目=链路核对）

```
POST /api/v1/search
{"limit": 5, "project_id": "<链路核对项目 id>", "query": "有没有哪种情况会让服务根本起不来", "scope": "project"}

HTTP 200
{"memories":[],"total":0,"offset":0,"next_offset":null,"truncated":false,
 "ranked":true,"retracted_excluded":0, ...}
```

期望：L1（标题"网关端口冲突阻塞联调"，正文"服务启动时报端口 8080 已被占用…"）进入前 5。
实际：空。断言依据：该 query 无空白分隔，整句作为一个中文词条参与 AND 匹配。

相关地，P3 的 `本地环境的外网访问凭据什么时候失效` 返回了 L1（`total=1`）——说明这套策略
对"部分 bigram 偶然命中"的句子会给出**看似有结果但答案不对**的返回，这比空返回更容易误导使用者。

### 4.4 过期内容（信息性，非失败）

| id | query | 期望 | 实际 | 说明 |
| --- | --- | --- | --- | --- |
| O1 | 绑定失败 | 无 | 空 | 旧正文已被 update 覆盖，`total=0`，符合"只返回最新版本" |
| O2 | 进程未退出 | 无 | L4 | L4 最新版本正文仍含"子进程会被终止"，命中是预期行为 |
| O3 | 备份任务 无法完成 | 无 | 空 | B4 最新版已改为"没有再中断"，`total=0` |
| O4 | 续期后上传恢复 | B4 | B4（v2） | 更新后新措辞可召回，版本=2 |

这 4 条用于确认"update 后旧措辞确实不再命中"（O1/O3），以及"仍在最新版本里的措辞仍会命中"（O2）。
`stale_outdated_false_recall = 2` 中的 1 条来自 O4（期望命中却归类在信息性类别），1 条来自 O2，均非缺陷。

## 5. 其它已实测的结论

- **跨项目隔离**：`scope=project` 的 48 条查询共返回 67 条记录，0 条属于其它项目（污染率 0/67）。
  `project_conflict` 类 10/10 命中且名次全为 1，
  说明"同一问题在两个项目有不同答案"时只召回本项目记录（如 C4 在"备份演练"返回 B4、C3 在"链路核对"返回 L6）。
- **个人维度**：`scope=personal` 的 10 条查询共返回 9 条记录，全部为 personal 记录。
- **撤回**：6 条已撤回类查询默认 `total=0` 且 `retracted_excluded` 均为 1；`include_retracted=true` 时 6/6 名次为 1。
- **无结果**：10 条跨领域查询全部 `total=0`，误召回率 0.0。原因是 AND 语义要求每个词条都命中，噪声词很难同时命中。
- **长句（≥25 字自然问句）**：10/10 命中、MRR 0.9500、名次为 [2,1,1,1,1,1,1,1,1,1]（仅 Q1 排在第 2）；
  但这些问句与夹具用词重合度较高，因此**不能**据此认为长句检索已经可用——
  4.1 的 15 条不照抄改写才是同一能力的真实水平。两类对比本身就是本基线的一个发现：
  当前策略"照抄措辞就能召回、换个说法就召不回"。

## 6. 已知边界（未测即未测）

- 本基线只覆盖**词条 + 中文 bigram** 的关键词检索；未测语义/向量召回（P3 明确不做）。
- 数据集规模 68 条查询 / 27 条记录，是刻意做小以便逐条人工核对，不代表生产分布。
- MRR 只对"有答案"的 49 条计算；`最新版本` 类 MRR 0.7778 仅来自 3 条查询，样本很小。
- 本文件不包含任何未实测的数字，也不包含"应该会更好"的推断。
