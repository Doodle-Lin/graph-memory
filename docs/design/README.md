# Graph Memory 重设计交付入口

> 2026-11-02 实施更新：主流程恢复为 Agent 经 MCP 自动检索与沉淀；桌面负责接入状态、浏览和纠正，手动复制仅备用。旧原型与下述阶段设计作为历史依据，最新运行方式见 [桌面说明](../../desktop/README.md)。已实现独立服务、范围隔离、版本修订和 Avalonia 开发版；迁移、语义检索、删除恢复等仍未完成。


## 产品判断
值得继续做的方向是“跨Agent、跨会话的可信项目上下文”，而不是更漂亮的图谱管理器。价值必须体现为减少重复解释、重复失败和遗漏阻塞，并扣除审核、纠错、接入成本。
这是经过多轮代码核对和反方审查后的设计选择，尚未取得真实使用收益数据。

## 六个已确定的取舍
1. Avalonia重做桌面端，保留Rust引擎，先拆出独立服务。
2. Agent是日常读写入口；桌面端承担查看、查证、纠错和恢复。
3. 项目、范围、来源、版本是基础；图谱放到辅助探索。
4. 未核实交接仍可帮助恢复工作，但不能包装成已验证事实。
5. 自动捕获关键事件，不要求每轮回答写入或用户逐条批准。
6. 第一版停止破坏性自动合并和自动遗忘；不同时重写检索算法。

## 当前状态
设计v1.0已收敛，用户确认“现在够直接，可以收敛设计”。产品主要路径已决策；独立审阅已处置；最终复核13条状态检查与1条模拟复制路径检查通过。
已收到初版反馈：未发现明显问题，但希望更简便。已将日常使用定义为已接入Agent自动续接，无需打开桌面；手动兜底只需“继续工作→复制”。用户已接受简化后的实际路径。键盘/缩放专项仍须在Avalonia实现阶段验证，不声称已通过。
未实施：Avalonia应用、独立Rust服务、新存储模型、真实MCP适配和真实收益试验。这些是后续实施目标，不能冒充设计阶段成果。

## 如何查看原型
自行用浏览器打开desktop-prototype.html。普通使用先尝试“继续工作→复制并用于新会话”，无需展开背景或核查。需要纠错时再打开对应记录；需要管理时尝试“项目数据→移除→切换项目→恢复”。检查是否知道当前项目、结论依据和下一步动作。管理里的目录/接入/导出均为模拟。
不需要阅读全部历史评审后才能评价；原型若要靠长篇解释才能用，应视为设计问题。
