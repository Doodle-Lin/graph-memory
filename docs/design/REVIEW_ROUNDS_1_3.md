# Graph Memory 产品重设计 — 工作稿

状态：设计审查中，未验证用户效果；不是实施完成声明。
日期：2026-11-02。用户明确要求：重新审视产品，桌面端迁移 Avalonia。

## 1. 产品决策与可证伪假设
面向同时用多个 Agent 推进多个代码项目的个人开发者。核心工作：跨会话恢复可信上下文，避免重复解释、重复失败和遗漏阻塞。桌面端是观察与纠错中心，Agent 接口是日常使用入口。
假设 H1：相比项目文档，跨来源状态汇集能减少续接准备时间。H2：自动捕获带来的审核成本低于节省时间。H3：来源和冲突展示让错误能被发现而非被更流畅地传播。
这些是假设，不把用户觉得旧端不好用等同于以上全部得到验证。
若对照试验不能证明净节省，先退回“可追溯的项目交接记录”，不扩大自动化。
不做团队协作、多端同步、通用文档库、自动任务执行、图谱编辑器。

## 3. 差异化与产品边界
AGENTS.md 适合维护稳定规则，项目文档适合正式方案，聊天适合完整过程。本工具聚合有出处的动态状态和尝试记录，不争夺正式文档的权威性。
项目文档与记忆矛盾时展示具体差异，不以“最新写入”自动选胜者。用户选择权威来源或确认状态。导出的上下文引用文档，避免静默制造第二份规范。
成功单位：一次有效续接；不以节点数、图谱规模、写入次数作为价值指标。

## 4. 对象与可信规则
Project：稳定 UUID，用户明确关联目录；路径只是定位信息，重命名不新建项目。首次未知目录询问归属，禁止仅凭相似文本跨项目合并。
Evidence：来源类型、定位、摘要/必要摘录、采集时间、内容指纹、可访问状态；来源失效保留“曾观察到”的历史，不声称当前有效。
Record：项目、类别（决策/状态/阻塞/尝试/下一步）、内容、证据、作者、发生时间、记录时间、版本、有效范围。
分开表达：生命周期（候选/当前/已替代/撤回）与依据（用户确认/工具结果/Agent 陈述/推断）。用户确认不等于工具验证；测试通过只对相应提交和测试范围有效。
Change：前后版本、原因、操作者、关联证据，用于比较与撤销。
ContextBundle：项目、任务、生成时间、输入版本、选中记录、排除原因和缺口。记录变更后旧 bundle 标为过期，不修改已交付历史。

## 5. 自动捕获与审核成本
捕获关键事件：决策形成、验证结束、阻塞出现/解除、交接、明确纠正。无需每次回答后写入。
V1 自动存的是带出处的记录；Agent 的状态声明不会自动升格为已验证状态。相似记录只提示关联，不自动破坏性合并。
没有可靠来源的新内容可存为候选，在上下文的“未核实陈述”分区展示，不参与事实断言。无法确认项目归属进入未归属区，不污染所有项目检索。
待处理只包含会影响当前任务的冲突与归属问题，按项目聚合；允许稍后处理且明确上下文缺口。不要求逐条审核所有捕获内容。
来源内容视为数据，不能成为执行命令或改变 Agent 指令的依据。敏感原文默认不进遥测；外部 LLM 提炼须显示发送范围并由用户启用。

## 6. 交互规格
首启：选项目目录 → 选一个接入方式 → 用合成记录检查服务与 MCP → 展示一份可检查的上下文。没有数据时不生成虚构进度；允许手工留一条带来源的交接记录。
常态入口：左侧项目，中间当前项目，右侧按需展开证据。首页显示当前状态、阻塞、下一步和最近变化；不默认展示全图。
主操作“继续此任务”：选择任务 → 预览上下文及缺口 → Agent 拉取或复制。复制是兼容兜底，自动读取是主流程；工具返回成功不能冒充 Agent 已采用。
记录详情：原文、来源、有效范围、版本。纠正按 ID + expected_version 提交；版本冲突展示差异，不覆盖他人修改。成功后重建受影响上下文。
冲突处理：并排展示结论、时间、来源；选择替代/并存且补范围/待确认。旧版可查看。撤销生成反向变更；若有依赖后续编辑，不允许盲目覆盖，进入冲突处理。
搜索默认当前项目；全局搜索必须显式切换并标明归属。检索可以展示旧记录，上下文不能把旧记录作为当前事实。
运行状态分别展示：未配置/配置存在/握手成功/最近调用成功及时间/失败。只有可观察调用记录才显示成功；“被采用”需引用或反馈证据，否则标未知。
异常：模型未就绪允许浏览和手工记录，语义检索标不可用；服务离线展示带时间的缓存只读页；来源缺失标记无法复核；任务中断显示可重试，不能假报完成。

## 7. Avalonia 迁移边界
Windows 优先，沿用本地 Rust 引擎与 MCP，拆出不依赖窗口生命周期的服务。Avalonia 承担展示、编辑、诊断与配置。具体版本/API 选型在技术验证阶段查官方文档，不在此稿中假定可行性已证实。
服务单实例、启动握手、协议版本检查；窗口关闭与后台服务退出分离并在设置中明确。旧客户端与新客户端不能同时执行数据迁移。
迁移先备份并验证可恢复，在数据库副本试运行；旧记录作为未归属/历史导入，不凭猜测全部变成已验证项目状态。保留原始 ID 和来源。
新 schema 降级不通过旧程序直接写入；失败回滚恢复迁移前副本，保留迁移后的新增数据供另行导出核对。
发布要求：安装/启动/退出/重启、键盘操作、缩放、长内容、错误恢复、备份恢复均有验收；不把“能编译”当作桌面端可用。

## 8. V1 闭环与优先级
P0：项目归属、来源和版本化记录、按 ID 纠错、项目上下文组装、MCP 读写及调用记录、Avalonia 查看/纠错/续接、隔离验收和备份恢复。
P1：批量导入预览、冲突处理效率、上下文长度优化、可逆合并。P0 禁用自动破坏性合并与自动遗忘。
P2：图谱探索、更广 Agent 适配、多平台；由真实需求决定，不承诺同时完成。
顺序：可复现事实集 → 端到端接口契约与桌面原型并行 → 独立服务与一条纵向闭环 → 故障/迁移验证 → 实际续接试用。

## 9. 验收设计
冻结数据集，包含事实、证据、项目、时间、预期当前状态、旧状态、阻塞和禁止断言；独立数据库种库，不读取用户生产记忆。记录数据集版本、模型、配置和运行版本。
至少覆盖：正确续接、无证据、已替代结论、并存不同环境、来源失效、跨项目同名、精确标识符、纠错后重新读取、并发编辑、服务中断、迁移回滚。
分层测量：检索 recall@5；上下文事实支持率/阻塞保留/项目隔离；Agent 回答的错误断言；用户续接时间和审核耗时。拒答不能靠几个关键词判定。
对照：同一任务和冻结来源，比较项目文档基线、旧工具、新工具；独立新会话，交替顺序，记录总耗时（含配置分摊和纠错）。不能把更多上下文作为新工具独享优势。
安全硬门槛：受测场景中不允许跨项目混入、无依据宣称完成、纠错错对象、丢失未解决阻塞、不可恢复迁移。有限测试通过不推断全面可靠。
价值门槛暂定：在至少三个项目的十二个续接案例中，净准备时间中位数减少 30%，错误续接不增加。它是发布决策阈值而非既得指标；小样本仅支持个人试用。

## 11. 第二轮自审：避免“可信机制”让产品无法使用
R1：候选记录一律不参与上下文会导致冷启动无价值。修订：允许出现在“未核实交接陈述”分区，保留作者与时间；不得混入事实区。无工具证据不要求用户逐条确认，用户可直接据此开始核查。验收：仅有一次 Agent 交接时能得到有用但不冒充验证的上下文。
R2：只存 project_id 不足以避免分支/部署环境混淆。修订：上下文请求带任务与可选 branch/commit/environment；缺少范围时不推断部署状态。不同范围的记录并存，不当作矛盾强迫二选一。验收：同项目两个分支的测试结果不互相覆盖。
R3：时间更晚的观察仍可能是旧事实重述。修订：区分 observed_at/effective_at/recorded_at；替代关系必须显式，不按时间或相似度自动覆盖。验收：今天导入上月日志不能替代昨天验证的状态。
R4：“MCP 自动使用”不可由工具单方面保证。修订：先支持一种已实测宿主；配置、握手、工具调用、回答引用四层分别记录。若宿主不调用，产品显示缺口并提供一次性恢复上下文入口，不声称已自动接管记忆。
R5：P0 过宽且可逆合并非前置。修订：第一纵向切片只含一个项目、一次带出处交接、一次按 ID 修正、一次 MCP 读取、一个 Avalonia 续接页；其后补齐第8节P0才可作为V1发布。切片不是缩小最终产品范围，也不是完成声明。
R6：桌面摘要本身可能幻觉。修订：V1 续接页从结构化记录确定性组装；可选 LLM 仅建议压缩文本，保留引用并可展开原文。不以未经验证的生成摘要更新当前状态。

## 12. 第三轮审查与取舍（Claude 仅审文本，主代理核实）
采纳：依据必须贯穿读路径。每个 bundle 条目必带 record_id、version、scope、依据类型、有效时间/未知、来源定位；陈述只能输出“某主体声称”，不可压缩成已验证事实。生成失败退回结构化原文，不移除限定。
采纳：明确最小冲突检测。相同 project + subject_key + 相交 scope 的单值事实不同，触发冲突候选；用户也可标记。subject_key 由结构化工具提供或用户确认，自由文本抽取只提供候选，V1 不保证发现任意语义冲突。scope 包含 repository、branch/commit、environment、有效时间窗；未知不能默认等同所有范围。
采纳：新增 TaskRef（id、project_id、标题、可选外部来源、active/paused/done）。默认由用户选中或交接中明确指定；自动提议需确认，不构建完整任务管理器。无任务时支持项目级恢复，不强迫维护任务列表。
采纳：离线视图来自客户端上次成功获取的只读快照，展示快照时间和版本；UI 不直接写/读数据库绕过服务。无快照显示空态。离线可保留本地编辑草稿，重连后版本校验再提交。
采纳：旧客户端不接入迁移后的正式库；迁移前关闭旧写入者，新客户端通过版本协议接入。迁移副本用于试运行，只有通过验证后切换。迁移失败恢复原库不丢弃新增导出。
采纳：本地调用日志默认仅记录工具名、项目、时间、结果、返回 ID/版本、耗时，不记录 prompt/原文/token；默认保留7天，可清除或关闭，详细内容记录单独选择启用并自动到期。关闭后采用状态显示不可观测。
采纳：增加导入恶意指令与凭据案例。导入内容不触发执行；本工具不执行来源中的命令；MCP 返回明确数据结构和来源。外发提炼前预览、排除敏感字段；扫描只是辅助，不保证识别一切秘密，默认不外发。Agent 自身越权不能由记忆工具完全保证阻止，验收中单独报告宿主行为。
部分采纳：Avalonia 迁移是用户明确要求，不能取消。可以在全面实现之前用轻量原型检验交互，并完成独立服务技术验证。产品价值实验不要求等待完整迁移。
拒绝：自动合并优于逐条审核的二选一。V1 可以保留重复记录并按来源/精确标识折叠展示，既不破坏数据，也不强迫逐条确认。旧自动去重/遗忘路径必须在接入新库前盘点并关闭破坏性路径，此项属于迁移实现门槛而非已完成修复。
修订验收：“有效续接”定义为新会话正确指出下一项可执行行动、保留所有影响该行动的阻塞、没有把未经支持的状态当事实，且不需要用户重复提供已有关键事实。记录达到此状态的时间及人工纠错时间。预注册事实判分表并保存原始输出，避免只挑成功案例；超过基线两倍耗时的案例逐个分析，不被中位数掩盖。
不采信审查附带的显著性数字与“只剩原型”的完成判断：未独立计算统计量，也未完成整体审计。当前审查完成的是文本漏洞定位，不是产品已被验证。
