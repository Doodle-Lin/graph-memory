## 已确认的技术边界

| 代码证据 | 对产品承诺的影响 | 实施要求 |
|---|---|---|
| lib.rs run/setup 创建引擎、服务器、托盘和窗口 | “关闭窗口仍提供记忆”不能仅靠替换UI实现 | 提取服务启动入口，窗口生命周期只负责客户端 |
| lib.rs 找不到 frontend 目录不启动HTTP；static_server.rs start_with_engine 验证root存在 | Avalonia部署不带Web资源时，现有MCP会失去服务 | API监听启动与静态资源完全解耦；无frontend目录也通过健康/读写 |
| lib.rs 模型加载借助AppHandle取AppState | 无窗口启动可能缺少模型加载与enrich | 将模型/维护任务归服务所有，进度转API状态 |
| EngineHandle为Arc<Mutex<GraphEngine>>，enrich持锁 | 后台工作可能阻塞读取，与“浏览不受提炼影响”有差距 | 度量长锁；分阶段处理/快照读取；无法立即读时返回明确忙碌，不假超时成功 |
| static_server.rs写固定用户目录port；MCP读取相同文件 | 多实例/测试隔离可能指向错误数据库 | 发现信息带实例ID、数据目录标识、协议版本；先校验身份后调用；测试独立发现路径 |
| MCP代理POST超时120秒，GET60秒 | 首启或故障可能让Agent长时间无反馈 | 健康握手短超时，长任务返回任务ID并查询；超时未知结果可按event_id查回 |
| Cargo.toml lib/build直接依赖Tauri | 新建exe不等于独立可打包服务 | core/service/legacy-ui模块边界或独立crate；service无Tauri/WebView运行依赖 |

## 实施阶段与退出条件

### M0：冻结产品契约（当前设计工作）
交付：现行PRD、流程表、验收输入、原型、设计审计。退出：没有尚未决策的产品主路径；原型覆盖关键动作；未验证假设明确。视觉检查尚待完成。

### M1：无窗口运行骨架
范围：只做服务启动、发现、健康、旧MCP代理接入；不改变检索排序。
退出：关闭或不安装旧UI、删除测试安装中的frontend资源后，服务仍能启动并用隔离库写读；两个启动请求只产生一个写入者；故障报告可理解。
回退：旧应用继续使用旧库；新服务仅测试副本。

### M2：可靠记录与上下文契约
范围：Project/Scope、事件幂等、依据/时间/版本、ID更新、上下文失效、日志、导出恢复。停用旧自动破坏性维护路径。
退出：固定案例A01-A04/B01-B04/G01-G04通过相应实际存储/接口断言；调用失败不冒充持久化；重复响应丢失不重复建记录。
回退：API兼容层隔离旧接口；旧工具不允许绕过新项目范围写正式库。

### M3：Avalonia一条纵向闭环
范围：项目导航、续接正文、证据侧栏、纠正/撤销、上下文预览、连接状态、首启。
退出：从空安装完成交接→关闭窗口→新Agent读取→用户纠错→再次读取新版本；键盘/缩放/长文/空态检查通过。浏览器原型不能代替Avalonia验收。

### M4：可试用版本
范围：升级迁移、来源失效、多项目草稿、降级、隐私与保留策略。
退出：备份恢复演练、新旧版本隔离、来源删除和服务崩溃恢复通过；进行预注册真实项目续接对照。
回退：不能达到净收益时停止扩大自动捕获与摘要，定位成本来源；不把失败掩盖为增加新功能。

## 范围控制
不编造日历承诺：在M1完成后根据实际拆分量估算，M2按存储/接口风险估算，M3按桌面交互复杂度估算。每阶段交付可演示闭环而非文件数。
首版适配器以真实宿主握手/写入/读取成功选择，不能仅凭本机配置文件存在选定。操作系统先Windows，其他平台不纳入首版门槛。
未确定：Avalonia/.NET版本、打包器、本地通信鉴权实现、后台服务托管方式；它们须用官方资料和最小技术验证定案，不能由PRD臆断API可用。

## 工作项验收模板
每项必须写：用户触发、前置状态、成功可见结果、失败可见结果、持久化影响、兼容/回退、对应验收ID。实现者不能用“已加接口”代替用户结果。


## 独立技术审阅处置（第七轮）
- 采纳阶段边界修订：M0冻结产品行为和接口契约，不要求提前锁定Avalonia/.NET版本与打包器。M1入口需先验证托管、通信身份、单实例机制；未验证不得称M1完成。产品行为已定：按当前用户运行、不需管理员安装系统服务，UI退出不自动终止已启用后台，显式退出服务可停止。
- 证据使用工作树文件SHA-256，见CODE_EVIDENCE.json。仅钉commit不能覆盖未提交改动；指纹用于判定后续代码是否仍是本次检查对象，不代表保留了完整历史快照。
- 单实例机制选择：按规范化数据目录获取进程持有的系统独占锁；发现文件不是锁，端口占用也不证明库已被占用。服务启动成功后原子发布实例身份，客户端握手校验；进程退出释放锁。具体Windows实现由M1验证。验收同时包括并发启动、持锁进程崩溃、旧发现文件与另一用户实例。
- 拒绝“必须保留静态Web服务”的额外要求：新产品明确迁往Avalonia，Web资源不是新正式服务的必需能力。若为过渡保留旧UI，则单独适配测试；不把旧页面兼容扩大为永久产品要求。
- 旧自动合并/遗忘：新服务默认关闭破坏性路径，保留旧库备份供回退，不做不可追溯自动恢复。迁移报告列出可识别的历史合并、历史证据不足和已无法重建的内容；未知不能标为迁移丢失，也不能宣称恢复成功。
- Avalonia投资是用户明确选择，保留；产品效果尚未证实的风险已在PRD披露。M1/M2可在接口层验证正确性与恢复能力，不将完成这些阶段冒充价值验证。
