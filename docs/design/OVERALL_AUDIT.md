1. **P1：旧入口迁移丢失工具限制。** AgentSetupService.cs:51 删除旧入口，53 只从现有 graph_memory_v1 克隆设置；只有旧 graph-memory 时，旧条目的限制及额外设置都被丢弃。隔离合成配置复现 disabled_tools 不在输出中。应保留/转换宿主限制；多个旧入口策略冲突时拒绝自动迁移，不能默认为无限制。现有测试只检查 v1 条目的限制保留。

3. **P2：自定义记录类型会产生伪草稿。** 服务/MCP 接受任意 kind；MainWindow.axaml.cs:62 只认识五类，ApplyMemory 将未知类型映射 note，HasDraft 随即判为修改过。用户只打开一条 kind=lesson 的记录，也会被要求先保存才能打开其他记录；保存会改成 note。依据静态代码路径，尚未开展此案例原生 UI 复现。应保留未知类型或统一 API 契约。
4. **P2：草稿仅存内存，关窗无保护。** MainWindow.axaml.cs:63 的草稿字典没有持久化，Closed 仅停止定时器、释放客户端，没有 Closing 检查。误关窗口会丢掉未保存编辑。跨项目切换保留草稿并不能覆盖这一风险。应本地恢复草稿或关窗明确提示。
5. **P2：发布入口仍分裂。** README 顶部虽提示新开发版，主要安装流程仍是 Tauri；根 SKILL.md 直接要求旧 retrieve/write，新的五工具约定在 desktop/AGENT_INSTRUCTIONS.md。新用户/自动安装器从根入口接入容易得到过时指令。应把新版作为默认入口，旧版单独归档且标清适用版本。

- **闭环已经存在：**独立服务、个人/项目范围、真实 MCP 写读纠正、event_id 幂等创建、版本冲突拒绝、修订历史、桌面纠正、接入备份与撤销、日期范围和分页。

- **续接缺少状态理解：**context 按最近更新时间取 40 条项目记录、20 条个人经验（303–304），有截断提示，但没有优先保留未解决阻塞、结论替代或过期撤回状态。不能把最近记录列表当作准确当前项目状态。
- **周/月报是素材筛选：**只有创建/更新时间，返回最新版本。没有 occurred_at、按期间变化日志或历史时点快照；导入日期不能代表事情发生日期，后来更新也可能改变旧期间的筛选结果。
- **数据控制缺口：**新库没有用户可用的软删除/恢复、导出导入、数据库备份恢复演练；接入配置备份不等于知识库备份。所有依据统一为陈述，没有证据验证和来源失效链路。
- **接入和采用不是同一件事：**本机 Codex 配置只有 graph_memory_v1，但本聊天工具目录仍是旧版。服务统计只按工具累计，无法区分宿主，也不能证明 Agent 在回答中采用了结果。一键写配置没有自动部署新版行为约定。
- **部署仍偏开发：**打包脚本复制 debug Rust 二进制；运行中更新需要处理文件占用、服务重启和客户端重新发现，尚无正式安装/升级回滚流程。未发现仓库 CI 工作流。Rust 构建仍有未使用项警告。
- **安全边界有限：**监听 localhost 并拒绝 Origin 请求，不是用户/宿主认证。HTTP 解析器读取 body 和每连接线程缺少总量限制。此次没有做浏览器攻击链、压力或多用户安全验证，不把未验证风险当作已成功利用的漏洞。
