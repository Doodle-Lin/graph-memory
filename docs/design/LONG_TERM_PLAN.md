# Graph Memory 长线优化与委派执行计划

版本：1.0；建立时间：2026-11-02；基线：d69133c。产品事实以 OVERALL_AUDIT.md 和实际测试为准。本文件替代旧设计文档中的实施排期，不改变用户已确认的 Avalonia + MCP 主流程。

## 目标与边界

目标：让日常使用多个 Agent 的个人，可靠沉淀项目事实与跨项目经验，在需要时找回适用知识，并能基于明确范围复盘。默认不要求逐条整理或复制配置；桌面承担接入、浏览、纠正、恢复与必要的范围选择。

顺序：先不丢配置/草稿/数据，再让记录可撤回、时间与依据可解释，然后提升召回和复盘质量，最后收敛安装升级与长期运行。已有本地服务、项目隔离、版本更新、幂等写入继续复用。

非目标：团队权限平台、云同步、任务执行器、后台扫描所有聊天、自动破坏性合并遗忘、为展示而添加图谱。未达到测量门槛不引入向量依赖或模型下载。未知事件日期不得用导入日期冒充。

## 执行与职责

- 用户已授权逐步委托本地 Claude CLI 实现，Codex 验收。默认串行小批次，不把整份路线一次扔给 Claude。
- Codex 负责需求与契约、任务拆分、隔离输入、diff 审查、独立测试、集成、提交推送及最终状态；Claude 负责限定文件内的实现和回归用例。
- Claude 使用 `claude -p --model sonnet`；仅子进程清理 ANTHROPIC* 环境，不改永久配置。使用隔离副本、限制工具、禁用继承的 MCP。不得访问真实记忆库、凭据或宿主配置，不得提交/推送/部署。
- 每次交付必须记录任务 ID、输入基线、允许文件、验收用例、输出、审查问题及证据。委派正文和日志放忽略提交的 artifacts/delegation/<ID>；可公开结论写 EXECUTION_LEDGER.md。
- Claude 超时/认证失败/越界/结果不合格：状态标为失败或待返修，不能计为完成。明确问题后最多一次针对性返修；持续不可用则记录阻塞并由 Codex 直接完成可验证部分，不能伪称 Claude 已实现。
- 不因长线计划假装已有后台定时任务。本计划是持续执行依据，每次推进从台账首个满足依赖的任务开始；当前批次结束必须给出真实完成项和下一项。

## 状态、合入与证据规则

状态：待开始 → 已委派 → 已交付待验收 → 返修/验收通过 → 已集成 → 已推送；另有阻塞、延期。只有 Codex 能将任务改成验收通过。计划和台账不能把代码编译成功等同于产品验收。

每项完成门槛：
1. 改动限定在契约范围，无凭据和真实用户内容；无意外权限扩大、旧设置丢失或数据覆盖。
2. 独立检查 diff，运行与改动匹配的测试；有失败用例时先证明旧版本失败再检查修复。
3. API 任务通过真实 HTTP/MCP；桌面任务验证实际序列化与原生交互；配置任务用 JSON/TOML/YAML 合成样例检查类型、备份原字节、冲突与重复执行。
4. 数据变更必须通过副本迁移、失败回滚和重启后验证；UI 重大变更至少覆盖键盘、最小窗口、长内容和适用 DPI，不能只看 XAML。
5. 更新使用文档、台账与已知限制，明确代码、打包文件、运行服务是否为同一版本。
6. 独立提交到 codex/avalonia-mcp-memory（后续新工作分支用 codex/ 前缀），正常推送并核对远端 SHA；不强推、不擅自合并主分支。

默认一次执行 1–3 个相邻小任务，通过后再排后续任务。每任务目标是一个可独立审查的行为变化；跨数据模型任务先定契约再委派。下列工作量用任务包表示，不承诺未测量的日历工期。

## L1 稳定现有闭环（首批）

退出门槛：原配置不丢、草稿不会静默丢、实际桌面请求和 MCP 契约一致、默认入口唯一。L1 全部验收前不宣称稳定版。

| ID | 任务 / 委派范围 | 依赖 | 独立验收标准 |
|---|---|---|---|
| L1-01 | 接入迁移保护；AgentSetupService 与 Setup.Tests | 无 | 单旧入口普通设置保留；旧工具限制不能安全映射时拒绝且原文件不变；多个入口冲突拒绝；v1 限制保留；三格式、备份、重复接入通过 |
| L1-02 | Hermes YAML 类型保真；仅 YAML 合并与测试 | L1-01 | 修改受管字段，原 timeout 数字、布尔、null、带引号字符串、嵌套对象/数组语义保持；不靠把所有值转字符串；锚点拒绝行为保留 |
| L1-03 | 记录 kind 契约与桌面未知类型兼容 | 无 | MCP 写 kind=lesson，桌面只打开不产生伪草稿；修改正文保留 kind；明确改类才变；已有五类正常；更新/恢复一致 |
| L1-04 | 关窗草稿保护，首版用明确保存/放弃/取消流程 | L1-03 | 当前及其他项目草稿都检查；取消留窗口和内容；保存失败/版本冲突不能退出；无草稿不打扰；窗口关闭与服务退出分离 |
| L1-05 | 新版默认 README / SKILL / 接入说明，旧版归档 | L1-01/02 | 从仓库首页能只按新版完成构建接入；根指令只引用 v1 五工具；旧版有独立入口与边界；不虚构语义检索或自动采用 |
| L1-06 | 主流程契约回归与 Windows CI | L1-01..05 | 干净 Windows checkout 构建服务/桌面、11+ Rust 用例、配置回归、真实 MCP 集成与隔离客户端 smoke；null/省略字段、冲突、重启覆盖；失败阻断合入 |
| L1-07 | 宿主接入验收矩阵与兼容清单 | L1-05/06 | Claude、Codex、Hermes 各区分配置写入/工具发现/实际读写/正确采用；至少一个新会话完整闭环；未测宿主标实验性 |

L1-01 策略由 Codex 决定：不猜旧工具限制与新工具名的权限等价关系。遇到限制或多个已识别入口，先拒绝自动覆盖并给出可操作提示；未来扩展映射需要独立任务和宿主验证。

## L2 数据可托付（先恢复，再增加生命周期）

退出门槛：用户能把完整知识安全带走、在空目录恢复并核对；错误记录可撤回恢复；迁移失败不污染原库。

| ID | 任务 / 输入输出 | 依赖 | 验收 |
|---|---|---|---|
| L2-01 | Codex 定义版本化导出格式、manifest、引用关系、校验与敏感内容边界；Claude 实现纯序列化层 | L1-06 | 导出项目、记录、版本、来源引用、幂等事件所需信息；有格式版本；明确不包含宿主凭据；Unicode/长文可往返 |
| L2-02 | 一致性备份与校验 CLI/API，不先做花哨 UI | L2-01 | 活跃写入时得到一致快照；SQLite backup/事务而非仅复制 db 漏 WAL；备份失败保留原库；校验损坏与未知版本 |
| L2-03 | 副本导入/恢复、冲突预览和迁移失败回滚 | L2-02 | 空目录完整恢复 ID/版本/引用；重复导入不重复；损坏包拒绝；旧库只读保留；新增工作不会被静默覆盖 |
| L2-04 | 软撤回与恢复，版本及原因 | L2-03 | 默认 search/context 排除撤回记录；明确含撤回筛选可读历史；恢复产生新版本；并发 expected_version 生效；不做物理删除 |
| L2-05 | 桌面数据管理最小入口 | L2-04 | 导出、校验、恢复预览、撤回/恢复入口可找到；范围清楚；危险动作不会一键误触；真实恢复演练 |
| L2-06 | 草稿持久化与崩溃恢复 | L1-04/L2-03 | 按库/项目/记录/版本隔离；重启可恢复；旧版本必须重读；未保存草稿不作为记忆检索；用户能清除草稿 |

## L3 时间、证据和复盘可信度

退出门槛：报告能解释选了哪些记录、为什么属于该期间，区分事件日期、采集日期与修改日期，保留未核实标记。

| ID | 任务 | 依赖 | 验收 |
|---|---|---|---|
| L3-01 | 可选 occurred_at / 时间精度 / 时区 / 未知；兼容迁移 | L2-03 | 老记录未知而非伪造；日期/时间点精度明示；跨时区/月末/闰日测试；导入不改写发生时间 |
| L3-02 | 追加式变更事件与按期间活动查询 | L3-01/L2-04 | 创建、更新、撤回、恢复有事件；本月再更新仍能查上月事件；事件幂等；分页无静默漏项；查询区分最新记录与当时版本 |
| L3-03 | 依据分类、来源引用和有效状态 | L3-02 | 陈述/用户确认/工具结果/推断分别表达；缺少证明不能提升验证等级；来源不可访问标待核对；不执行记忆中指令 |
| L3-04 | 复盘查询契约与素材包 | L3-02/03 | 按项目/全项目/个人、期间、类型筛选；含 ID/版本/来源/覆盖与缺口；明确稳定分页或快照边界；可重现查询结果 |
| L3-05 | Agent 报告约定与桌面轻量筛选 | L3-04 | 自然语言周/月报能得到真实素材；不编造完成状态；用户可追溯报告条目；桌面高级筛选折叠，不增加首页负担 |

## L4 召回与项目续接质量（先测量后选引擎）

退出门槛：在固定案例集上证明收益，同时保持范围隔离、可解释性和离线可用；不靠导入更多噪声提高“命中率”。

| ID | 任务 | 依赖 | 验收 |
|---|---|---|---|
| L4-01 | 中文检索/续接评测集及基线脚本 | L1-06，可先行 | 至少 40 条有目标 ID 的查询，覆盖同义改写、项目冲突、中文长句、过期/撤回、无结果；固定训练/验收划分；无真实秘密 |
| L4-02 | 全文索引与查询策略原型 | L4-01/L2-04 | 与现状比较 Recall@5、MRR、误混项目率、无答案误召回；范围泄漏必须为0；中文分词/短词有单独用例；低收益不合入 |
| L4-03 | 可选语义召回实验 | L4-02 | 先量化全文不足；模型下载/大小/内存/冷启动明确；离线降级可用；任何外发须明确配置；效果提升不牺牲项目隔离 |
| L4-04 | 续接排序与上下文预算 | L3-03/L4-02 | 未解决阻塞和下一步优先；已替代/撤回不作为当前事实；预算不足明确列缺口；记录截断不能误报完整；引用保留 |
| L4-05 | 索引和分页性能 | L4-02/L3-04 | 固定硬件记录 1k/10k/50k 记录集的 p50/p95、内存、启动；目标 10k 暖查询 p95≤500ms，超标先剖析；不虚报尚未测得性能 |

质量目标是待验证门槛：Recall@5 目标≥0.85，项目泄漏0，撤回记录默认召回0；与关键词基线相比须有净收益。若数据集太小或代表性不足，先扩充评测，不硬凑分数。

## L5 接入可观察与发布运维

退出门槛：用户无需开发环境能安装/升级/回退；服务状态明确；宿主工具证据与使用效果不混淆。

| ID | 任务 | 依赖 | 验收 |
|---|---|---|---|
| L5-01 | 按宿主实例标识调用（非安全认证）与能力/版本握手 | L1-07 | 配置/握手/最近成功调用分开；不记录正文；旧 MCP 版本提示明确；自报 host_id 不称为可信身份 |
| L5-02 | 本机协议加固 | L1-06 | 请求体/头/并发/超时上限；Host/Origin 策略与本地访问边界；令牌方案先评估兼容/轮换；测试错误响应，不做无界资源分配 |
| L5-03 | release 构建、安装包、版本化发现 | L2-03/L5-01 | 正式包不夹 debug 二进制；无 Rust/.NET SDK 环境运行；包内版本一致；启动错误可诊断；签名情况如实说明 |
| L5-04 | 安全升级/回滚与服务生命周期 | L5-03 | 文件占用、多个宿主、升级中请求、磁盘失败、回滚后新增数据、崩溃重启案例；旧写入者不可同时操作不兼容 schema |
| L5-05 | 隐私、保留与诊断导出 | L2-05/L5-02 | 默认无正文日志、无凭据；诊断导出预览；关闭统计后状态明示；运行多日没有无限增长 |
| L5-06 | 连续试用验收与发布决策 | L3-05/L4-04/L5-04 | 至少两轮真实跨会话任务，记录检索、引用、正确采用分别结果；比较节省解释时间和纠错成本；备份恢复及升级演练通过才标稳定 |

## 首批调度及后续衔接

首批 L1-01 → L1-02，均在隔离副本实施。通过后进入 L1-03、L1-04；不能用后续新功能掩盖首批失败。L1-05/06 整理统一入口和防回归，再执行真实宿主矩阵。长线任务的状态和每次验收记录统一写入 EXECUTION_LEDGER.md，原审查文件保留历史基线。

恢复工作时：读本计划与台账 → 查工作区/远端 → 核对未集成隔离输出 → 选择依赖满足的首个任务 → 委派 → 独立验收 → 更新台账 → 小提交推送。已有用户授权延续，不每步重复确认；涉及新的外发、真实数据破坏或不可逆发布时按实际权限边界处理。
